# Условия эксперимента

## Реализация

Исходное задание — TASK.md, коммит исходного стенда 1c6e250 (45 строк).
Слишком подробный первоначальный вариант был заменён до запуска всех участников.
API, архитектура, библиотеки и механизм идемпотентности оставлены на усмотрение агента.
Qwen исключён до начала эксперимента из-за проблем с KYC/оплатой.

Каждому агенту была предоставлена отдельная VirtualBox VM с Arch Linux XFCE,
4 ГиБ RAM и 2 vCPU, созданная из одного базового снимка. Общие папки хоста,
общий буфер обмена и drag-and-drop отключены. Работа велась в гостевой ФС,
а не в общей папке. VM использовали NAT и отдельные порты SSH на хосте.
В базовом снимке установлены все клиенты; это изоляция решений, а не сокрытие
факта наличия других клиентов. Одновременно запускали не более двух VM.

Версии, зафиксированные пользователем: Go 1.27.3, Docker 29.9.2,
Docker Compose 5.7.0, Node 26.13.0, Git 2.56.0, VirtualBox 7.2.22r175245.
Модели и версии клиентов перечислены в manifest.json. Режим рассуждения — High.
Равное название режима у разных провайдеров не означает равный вычислительный бюджет.

Стартовый запрос для всех:

> Прочитай TASK.md и полностью выполни задание. Самостоятельно принимай технические решения, запусти необходимые проверки и исправь найденные ошибки. Соблюдай ограничения из TASK.md. В финальном ответе перечисли выполненные проверки, их результаты и оставшиеся ограничения.

Общий лимит времени или токенов заранее не фиксировался. Затраты и число ручных
подтверждений не собраны систематически. Сравниваются связки «модель + агент +
провайдер + настройки», а не изолированное качество базовых моделей.
У Kimi отмечен лимит 3 API-запроса в минуту; у Codex были паузы между этапами
из-за лимита подписки. Время из интерфейсов не является единым стандартизованным
измерением длительности. Повторных прогонов реализации для оценки разброса не было.

## Перекрёстные ревью

Каждый из пяти участников проверил четыре чужих решения — всего 20 пар,
без самопроверок. Для каждого ревью использовался отдельный клон исходного
снимка и новая сессия. В VM передавалось только проверяемое решение и инструкция;
чужие отзывы не передавались. Имена авторов и оригинальная Git-история не
включались в пакеты; это не гарантирует невозможность угадывания автора по стилю.

Общая инструкция охватывает корректность, конкурентность, идемпотентность,
сохранность данных, миграции, тесты, архитектуру и безопасность. Проверяющим
разрешено выполнять тесты и запускать собственные базы PostgreSQL в Docker.
Исправлять исходники запрещено; результат — только файл отзыва. Тексты
инструкций находятся в review-prompts/; они различаются именем выходного файла.

Первое предварительное ревью Kimi → Claude было повторено в чистой VM после
явного добавления архитектуры и безопасности. В опубликованный набор включено
только повторное ревью по расширенной инструкции. Все 20 официальных отзывов
собраны по этой инструкции.

Вначале после сбора сравнивались исходники и выданные пакеты. Для первых четырёх
собранных отзывов (Kimi → Claude, Codex → Claude, GLM → Codex, DeepSeek → GLM)
сравнение подтвердило неизменность исходных файлов. Затем по решению пользователя
при сборе проверялось только наличие непустого отзыва. Публикуемые реализации
всегда берутся из исходных архивов до ревью, а не из рабочих папок проверяющих.

## Окружение и ограничения проверки

В гостевых дисках не хватало места. Во время первого официального ревью Kimi
потребовалась очистка образов, описанная в отзыве. В последующих свежих VM
перед ревью удаляли Docker-образы и кэш сборки, получая около 6,3 ГиБ свободного
места. Это могло влиять на длительность и объём скачивания зависимостей.
Один запуск GUI VirtualBox аварийно завершился в Qt; дальнейшие VM запускались
без графического окна. Некоторым клонам Claude требовалась ручная авторизация
через GUI до начала ревью. Эти действия относятся к подготовке окружения.

Сборщик репозитория не запускал тесты всех пяти решений и не воспроизводил
все замечания. Отзывы могут содержать ложноположительные выводы, пропуски и
разное понимание приоритетов. Количество замечаний само по себе не является
оценкой качества реализации или проверяющего. Архитектурные рекомендации,
расхождения с добровольно заявленным README и нарушения TASK.md следует
рассматривать отдельно.

## Упаковка

Пять оригинальных архивов сохраняются у организатора. При сборке в Git
перенесены исходные файлы с сохранением байтов, включая README и TASK.md.
Исключены оригинальные каталоги .git и скомпилированный codex/bin/server.
Создана новая общая история: задание и описание → реализация → четыре отзыва.
Дополнительный каталог benchmark/ содержит только материалы эксперимента.
Отзывы перенесены побайтно, без исправлений формулировок и замечаний.
Контрольные суммы находятся в manifest.json.
