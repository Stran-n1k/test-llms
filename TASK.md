# Go-сервис бронирования мест

Создай небольшой, законченный backend на Go с PostgreSQL для бронирования
мест на событиях. Он должен позволять создавать события с ограниченной
вместимостью, смотреть доступность, бронировать несколько мест одним запросом,
просматривать и отменять бронирования.

## Обязательные свойства

- Данные сохраняются после перезапуска приложения.
- При конкурентных запросах нельзя продать больше мест, чем есть.
- Повтор одного запроса создания бронирования не создаёт дубликат.
  Сам выбери и опиши механизм, позволяющий клиенту безопасно повторить запрос.
- Отмена возвращает места ровно один раз, в том числе при повторных
  и одновременных запросах отмены.
- Эти гарантии действуют и для двух экземпляров сервиса с общей базой.
- Некорректные запросы получают понятные ошибки и не портят данные.

## Что предоставить

- Работающий HTTP JSON API. Сам спроектируй маршруты, форматы запросов
  и ответов, идентификаторы, структуру проекта и схему базы данных.
- Dockerfile и compose.yaml для приложения и PostgreSQL.
- Воспроизводимую подготовку схемы на пустой базе без потери данных
  при повторном запуске.
- Автоматические тесты основных сценариев, включая конкурентность
  и работу с настоящей PostgreSQL.
- README с командами запуска и тестирования, примерами запросов,
  принятыми решениями и известными ограничениями.

Для одинакового запуска используй DATABASE_URL для подключения к базе
и HTTP_ADDR для адреса HTTP-сервера. Зависимости зафиксируй в go.mod/go.sum.

Не нужны авторизация, пользовательский интерфейс, Redis и Kubernetes.
Архитектуру, библиотеки, транзакции и детали поведения выбери самостоятельно.
Разумные допущения зафиксируй в README; не останавливайся ради согласования
обычных технических решений.

Реализуй решение, запусти подходящие проверки и исправь обнаруженные ошибки.
В финальном ответе перечисли фактически выполненные проверки и ограничения.

Работай только в своём проекте. Не изменяй TASK.md, не читай решения других
участников и не используй других ИИ-агентов или субагентов. Не используй sudo,
не меняй глобальные настройки и не удаляй посторонние контейнеры, тома и файлы.
Скачивать зависимости и запускать собственную тестовую базу в Docker можно.
